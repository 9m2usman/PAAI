# PAAI Production Runbook

## Configuration

Copy `.env.example` to `.env` and configure:
- `GROQ_API_KEY`
- `PAAI_AUTH_SECRET` (random secret, at least 32 characters)
- `PAAI_CREDENTIAL_ENCRYPTION_KEY` (Fernet key generated by `CredentialCipher.generate_key()`)
- Explicit `PAAI_CORS_ORIGINS` for trusted frontend origins.
- Google OAuth values only when Google integrations are enabled.

Never commit `.env`. Store production secrets in a managed secret store, not in the container image.

## Local container

```powershell
docker compose build
docker compose up -d
docker compose ps
docker compose logs -f api
```

Check `http://localhost:8000/health/live` and `/health/ready`. The API listens on port 8000. Place it behind a TLS-terminating reverse proxy before exposing it publicly.

## Worker

Run the background worker as a separately supervised process:

```powershell
.\\venv\\Scripts\\python.exe -m app.production.worker_main
```

The worker must use the same persistent data directory and authentication configuration as the API. Configure a process supervisor to restart it and forward SIGTERM for graceful shutdown.

## Backups and recovery

Stop writes or use a consistent SQLite backup mechanism before copying database files. Back up authentication, memory, and autonomy databases together. Protect backups as sensitive data. Periodically test restoration into an isolated environment.

## Operational checks

- Verify health endpoints after deployment.
- Monitor application logs and request IDs.
- Alert on repeated worker failures, due-goal backlog, authentication failures, and database disk exhaustion.
- Rotate authentication and encryption keys using a planned migration; changing keys without migration invalidates tokens or encrypted credentials.
- Keep TLS, host firewall, OS patching, secret storage, and database backups configured at the hosting layer.

## Current deployment boundary

The included Docker Compose file is a single-host learning deployment using SQLite. It is not a multi-region or horizontally scaled deployment. Do not run multiple API/worker replicas against the same SQLite files without a deliberate locking and shared-storage design. A production multi-instance deployment should move to PostgreSQL and a shared job/lease backend.

The credential cipher is a cryptographic building block; the existing in-memory Phase 5 CredentialManager has not yet been replaced with an encrypted persistent vault. Do not interpret the presence of the helper as proof that OAuth credentials are encrypted at rest.
